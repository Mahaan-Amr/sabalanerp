# Require verified zero-data-loss deployments

Production releases use a short fail-closed maintenance window and a coordinated Release Checkpoint covering PostgreSQL, Inquiry SQLite, business-owned files, recovery coordination data, configuration identity, and immutable application image digests. No migration or other mutation may begin until the encrypted local checkpoint and its independently stored remote copy have both passed manifest, checksum, capacity, compatibility, and restore-readiness checks; any mandatory post-migration gate failure triggers one journaled automatic rollback to the previous complete release set, while an unprovable rollback leaves the system in maintenance for controlled recovery. This deliberate availability trade-off prioritizes zero acknowledged-write loss and reproducible recovery over uninterrupted deployment, and permits no force or bypass path.
