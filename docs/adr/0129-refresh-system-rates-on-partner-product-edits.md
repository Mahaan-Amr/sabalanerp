# Refresh system rates when Partner products or services change

An unchanged main-stone inquiry subject does not mean the Product's operations are unchanged. Reusing the complete previous technical context hid newly selected tools, finishing and layers and rejected legitimate edits. Partner product/service edits now capture current trusted rates for all selected cuts, tools, finishing, layer types and independent services. The user chose complete system-rate refresh over carrying forward unchanged component rates so the new agreement reflects current system charges.

Refresh occurs only when technical/commercial product or service intent differs from the last validated save; checkpoint counters, display-unit/control-origin preferences with unchanged canonical geometry, page opening, recovery, printing and Customer/address/delivery/payment-only edits do not trigger it. Preview uses the same decision and current sources as validated save. Successful saves seal a new immutable snapshot; failed saves preserve the last valid snapshot and recoverable edits. Idempotent retries replay the same recorded result.

Manual Customer material and service prices remain unchanged. Main-stone responder identity and quoted rate follow the existing Case inquiry rules (ADR-0113 and ADR-0121); this decision neither broadens that identity nor silently replaces quotes. Historical finalized records, PDFs, accounting evidence and prior approvals are never rewritten. Existing correction authority and commercial reconfirmation rules still apply.

The selected physical definition and its catalog version remain recorded. Current ancillary rates carry their own source version in private evidence, independently of that physical snapshot. Previously selected catalog definitions may survive rate-version drift, but changed calculation units require correction. New selections must match the selected catalog revision. Identity includes component kind, catalog ID and version; identical display names never merge tools and finishing.

An inactive, missing or invalid-rate selected component blocks product/service edits with a bounded public Persian message naming the component; it never falls back to its former rate. Explicit zero rates retain their existing domain meaning, while layer types still require their positive catalog rate. Unchanged reads/saves retain their prior evidence even if the current catalog is unavailable.

This supersedes the Partner-specific frozen-rate and inactive-layer-resave clauses in the glossary's `نرخ نوع لایه پله` for product/service edits. Ordinary Sale behavior, historical rendering and saves with unchanged product/service intent retain those clauses. It narrows ADR-0111's preservation of historical graphs to prior snapshots rather than carrying all ancillary rates into an edited successor.
