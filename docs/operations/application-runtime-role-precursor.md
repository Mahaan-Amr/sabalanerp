# Application runtime role precursor (#456)

This is a fail-closed control-only preparation for an **isolated restored PostgreSQL target**. It is not a runtime credential cutover, a business grant manifest, or allocation activation. Production Compose, the protected runner, and the closed allocation guard remain unchanged.

Run `deploy/sql/prepare-application-runtime-role.sql` with a privileged protected operator through `psql -v ON_ERROR_STOP=1` after a `pg_restore --no-owner --no-privileges`. Reapply it after every such restore. It creates `sabalan_application_runtime` with `NOLOGIN`, no password, no membership, and no grants. Reapplication checks the same attributes and ownership and refuses to repair a changed role silently. Because PostgreSQL roles are cluster-wide, use the authorized isolated target and verify its identity before running. This SQL does not create a login credential or change the running backend.

Run `deploy/sql/audit-application-runtime-role.sql` through the same protected connection after preparation. It prints effective privilege inventory for every current public relation, sequence, and function; it refuses unsafe role attributes, membership, ownership, schema/database `CREATE`, access to the named migration, deployment lease, allocation control and allocation audit relations, and execution of the two allocation controller functions. It then deliberately fails with `APPLICATION_RUNTIME_GRANT_MANIFEST_NOT_REVIEWED`. A zero exit code is therefore **not expected**. Keep the report in private QA evidence if it includes object names that should not be published.

The local `sabalanerp-local` catalog on 2026-11-16 contained 571 public relations, four sequences, and 390 public functions. The backend source contains more than 1,300 raw SQL call-site matches, including tests. These numbers are diagnostic only and can differ on a restored target. The next grant increment must inventory actual backend queries, jobs, recovery entry points and installed image behavior; classify each relation, sequence, and callable function; name permitted operations per object; revoke unintended `PUBLIC` function execution where needed; and reapply that reviewed manifest deterministically after a no-ACL restore. No `ALL TABLES`, blanket default privilege, or broad function grant belongs in that manifest.

## Version 2 object inventory (still closed)

`deploy/manifests/application-runtime-objects-v2.json` freezes 985 exact public relation, sequence, and function identities from a temporary database inside the existing `sabalanerp-local` PostgreSQL service. The source database was copied with `pg_dump`/`pg_restore --no-owner --no-privileges`; the 16 missing repository migrations were then applied in order through the candidate head `20261116133000_customer_allocation_controller_transition`. The snapshot includes the allocation release control/audit relations and both controller functions. Its provenance records the head migration SHA-256 and a SHA-256 of the sorted applied migration-name/checksum ledger. Five historical ledger entries have no current repository directory, and one already-applied dashboard migration checksum differs from the current file; those are explicitly recorded in the snapshot and prevent treating this as an exact production or clean-from-zero migration proof. The temporary database was dropped after capture.

The top-level review remains `UNREVIEWED` with empty default grants; all 985 objects therefore inherit no proposed grant. The read-only `deploy/sql/inventory-application-runtime-objects.sql` emits the same versioned object format with owner and security-definer status. It fixes the catalog formatting search path to `pg_catalog` and fully qualifies function names, so the caller's search path does not change identities. Feed its single JSON row to `deploy/scripts/check-application-runtime-object-inventory.mjs`; the checker rejects missing, added, duplicate, malformed or changed identities and owner/definer drift, and always exits nonzero while grants or a provisioner are absent. The snapshot is a planning inventory, not a permission manifest or production-state inventory. Never pass its empty grant list to a generic grant applier.

The blocking review work is concrete: classify all 985 objects against actual backend queries and jobs, distinguish business mutations from migration and deployment lease operations, review `PUBLIC` function execution and default privileges, resolve the recorded historical checksum divergence, and establish the exact restored-schema ownership after `pg_restore --no-owner --no-privileges`. `backend/src/routes/system-recovery.ts` still invokes database stage/promotion from the long-running backend through `DATABASE_URL`; that path creates and renames databases. It needs a separately authorized protected control-plane route before a restricted backend credential can serve the existing ADMIN recovery feature. Do not grant database `CREATE` or ownership to the runtime role to keep that route working. The local backend was restarting during this inventory, so it did not supply a qualifying application read/write journey. No direct restricted-login positive test or runtime cutover is claimed.

Before a login is enabled, direct authenticated application sessions on a restored QA database must prove ordinary reads and writes, readiness, jobs and recovery boundaries. Negative probes must show the login cannot `SET ROLE` to bootstrap/control/controller, impersonate another session, migrate, own or alter objects, touch deployment lease/control/audit rows, execute allocation activation, or open the closed allocation guard. The `NOLOGIN` test only proves direct connection refusal at this preparatory stage. The existing superuser `SET SESSION AUTHORIZATION` tests are diagnostics and do not establish isolation.

Do not put the future runtime password in the backend until exact previous environment bytes and privileged control credentials are protected across checkpoint, rollback and interrupted recovery, as required by `customer-allocation-activation-plan.md` and `zero-data-loss-deployment.md`.
