# تحویل ادغام حضور دستگاه با ferpheri

تاریخ: ۱۷ اکتبر ۲۰۲۶. دامنهٔ مجاز فعلی، ادغام و push به `ferpheri` است؛ انتشار ابری و فعال‌سازی حضور خودکار مجاز نشده‌اند.

کاندید حضور R3 با commit `fdc64a783ca47a9d059f5ef9cad5639287d9c47c` با تغییرات ریموت `ferpheri` تا `df59b0080e86790fea9c141bad948889d3fda8e9` ادغام شده است. همهٔ تغییرات حسابداری ریموت حفظ شدند. در آزمون مرورگر، فرض راه‌اندازی‌شدن حتمی دفترکل محلی اصلاح شد؛ آزمون اکنون پاسخ واقعی context، حالت پیش‌نیاز و نبود درخواست نوشتنی مالی را بررسی می‌کند. منطق مالی برای عبور آزمون تغییر نکرده است.

## وضعیت حضور و PDF

- اتصال دستگاه فقط در حالت مقایسه‌ای `SHADOW` راه‌اندازی شود؛ ثبت خودکار خاموش و `activatedAt` خالی بماند. این تحویل اجازهٔ provisioning ابری یا تغییر خوانشگر Windows نیست.
- پرونده‌های ایمان طاهری، علی بهپور و آریا متانت تا تأیید واقعیت‌ها pending بمانند؛ migration یا script خودکار نباید آن‌ها را اصلاح یا ساعت حدسی ایجاد کند.
- ثبت دستی و حضور دستی نگهبان‌ها حفظ می‌شوند. قالب و تنظیمات PDF گزارش کارکرد نسبت به R3 تغییر نکرده‌اند.

## موانع انتشار ابری

طبق بررسی خواندنی ۱۷ اکتبر از حدود ساعت ۱۳:۲۹ تهران، ابر هنوز commit `cce0fa8da6b33f9218c8fb48eeca0d60c573d283` را اجرا می‌کرد. سرویس‌ها healthy بودند؛ ClamAV با engine نسخهٔ 1.4.5 و بانک 28138 مربوط به ۲۹ سپتامبر کار می‌کرد، اما updater آن defunct بود و آخرین لاگش HTTP 403 داشت. تعمیر محلی، تعمیر ابر محسوب نمی‌شود.

تطبیق همان snapshot با نسخهٔ ادغام‌شده، checksum برابر برای ۴۲۵ migration موفق و **۱۴ migration معوق** نشان داد: هفت migration قبلی R3 و هفت migration حسابداری ریموت. تعداد هفت در گزارش‌های قدیمی صرفاً برای R3 پیش از ادغام بود. پیش از اجرا، ledger واقعی ابر دوباره با commit نهایی تطبیق داده شود؛ هیچ migration انتخابی، force یا bypass مجاز نیست.

علاوه بر updater و تازگی امضاها، روش برخورد با سه هم‌پوشانی، imageهای نهایی با digest معتبر، checkpoint تازهٔ رمز‌شدهٔ محلی و مستقل، احراز بازیابی و ظرفیت، و مسئول/پنجره/مجوز انتشار باید تعیین تکلیف شوند. ادغام در `main` به‌تنهایی مجوز deploy یا گواه آمادگی تولید نیست.
