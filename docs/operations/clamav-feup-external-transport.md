# Fixed FEUP transport for the existing ClamAV container

This standalone host infrastructure helper restores verified HTTPS access from the exact enrolled ClamAV network namespace through the existing private HTTP CONNECT proxy. It forwards opaque TLS to mirrors.fe.up.pt:443; certificate and signature verification remain with the original clients. It does not update application containers, database schemas, ClamAV configuration, signature files, scheduler settings, or release health gates.

The versioned service file is a SOURCE TEMPLATE: it deliberately starts in `serve` mode, uses `Restart=no`, and contains a profile checksum placeholder. Do not copy it over the already qualified production route service. The actual installed route unit differs only in the reviewed profile checksum and ExecStart `serve` to `route` transition. CAP_SYS_PTRACE is required to open the exact pinned container namespace; the bounded service also requires its existing listed capabilities. Its gateway joins only the target network namespace, keeps host PID/mount namespaces, drops gateway identity, and binds loopback port 10443. Proxy traffic is not encrypted by HTTP CONNECT itself; upstream TLS remains end to end.

Enrollment is explicit and pins container ID, immutable image, StartedAt, host PID birth, network namespace inode, network identity, resolver, executables, helper checksum, existing xtables lock identity, and existing IPv6 isolation state. Never reuse a profile after a container replacement or host reboot. Changed incarnation must fail closed. Enabling the service does not provide automatic reenrollment; controlled reenrollment and qualification are still required. Backup restoration must establish the same infrastructure prerequisite with the actual restored target identity before claiming a complete restore.

Qualification sequence: acquire the existing deployment lease; verify exact source, environment, service census, and original live target; qualify SERVE with ordinary verified HTTPS HEAD; prove closure of the original monitor/gateway and qualify a new SERVE invocation; enable ROUTE only after that evidence. ROUTE uses an exclusively created chain and a new ownership nonce, redirects only measured FEUP IPv4 destinations on TCP443, and proves the real redirected TLS path using a counter increase. DNS expiry independently closes the original gateway. Existing AAAA records are permitted only when the unchanged kernel configuration and actual ENETUNREACH probes prove that IPv6 cannot leave the enrolled namespace.

Restart qualification must prove original monitor/gateway pidfd exit and reap, removal of the exact owned chain, unchanged foreign NAT, a new monitor/gateway invocation and nonce, and new native TLS/counter proof. A deliberate systemd stop can kill an in-flight readonly child query and leave the unit `failed`; do not call that a normal exit or blindly reset failure. Reconcile the exact closed pair, MainPID 0, absent owned NAT, unchanged foreign NAT and protected state before starting the same owned unit. Create and durably fsync only the service's own enable link after qualification. Never flush foreign chains, stop the natural updater, force FreshClam, change cooldown, or treat proxy readiness as updater health.
