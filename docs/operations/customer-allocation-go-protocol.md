# Grouped customer allocation GO decision: dormant verifier

`deploy/scripts/lib/customer-allocation-go-manifest.mjs` verifies a version 1 Ed25519 signature over canonical JSON. Its public interface takes the signed payload, independently observed release facts, and a pinned independent approver public key and key ID. It returns a manifest hash only when the decision is `GO`, the operation is `GROUPED_ALLOCATION`, all exact identities and evidence hashes agree, the decision is at most five minutes old, and the observed protected phase and lease are live. The evidence map requires reader, populated QA, and rollback receipts; the cohort hash binds the approved population. Candidate and predecessor image maps must each contain exactly backend, frontend, and inquiry and match the observed maps exactly.

This is an offline verifier, not an activation command. The three manifest image roles describe application images. They do not replace the protected controller's separate custody checks for all six service images and the rollback set. Its `observed` argument is only trustworthy when the protected controller obtains it from immutable installed image custody and a single locked `deployment_operations` row, then samples `clock_timestamp()` after the lock. The controller must also compare the target commit and release identity, recheck the evidence artifact hashes and independent approval key custody, and ensure no other application or process can construct an activation decision. A caller supplied observation object is not authority.

The next reviewed seam is the existing protected `deploy/scripts/deploy.sh` path immediately after `MIGRATIONS_APPLIED`, before release start. Under its drain, verified checkpoint and live lease, it must call the verifier and conditionally change a controller owned durable control row in the same database transaction as the locked operation check. That requires a new migration replacing the current `CHECK (state = 'CLOSED')` and immutable trigger with narrowly granted controller transitions and audit evidence, a transaction scoped runtime guard tied to build attested image identity, a closure path, and a release health gate comparing row, receipt and effective runtime identity before `TRAFFIC_OPENED`. Qualify the exact predecessor rollback reader and populated data rehearsal before this work is admitted.

The current control row remains structurally `CLOSED`; `requireCustomerSourceSharesWithin` still rejects every posting. No environment variable, request, command, or this verifier can activate it.
