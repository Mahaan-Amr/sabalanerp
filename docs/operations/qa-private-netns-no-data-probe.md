The actual D:-backed WSL distro is **`sabalanerp-qa-debian`**, with PID 1 `init` and `/etc/wsl.conf` containing `[boot] systemd=false`. The earlier version of this runbook used `systemctl` to stop, mask and start Docker and slirp units. The host evidence is in [the #439 WSL report](../../reports/qa/protected-rehearsal-439-wsl-host-20261112.md).

The 2026-11-14 read-only census after Docker Desktop relaunched narrows the next design to a **zero-state-only** owner: no `dockerd` process, `/run/docker.sock`, `/run/docker.pid`, `/var/lib/docker/containers` child, or named network namespace was present. The initial inode was `net:[4026531833]`; the six Desktop local services were healthy. `slirp4netns` was absent. Debian's apt metadata offered `slirp4netns` `1.2.1-1.1` amd64 with package SHA-256 `c294a4df952b9ae54e19e0ab19ac09a7e398fbf7aa8969cfcae07f92dc4f30ac`. `ip`, `iptables-save`, `curl`, `ssh`, `sftp`, and `node` were present; `dig` and `python3` were absent. This census is a momentary observation, not permission to assume zero state later. A future launcher must repeat it immediately before creation and refuse on **any** existing daemon, socket, PID file, container record, or named namespace. The owner chose the no-systemd Debian image to avoid the observed Ubuntu startup instability. A switch to systemd would require a separately reviewed host decision and bounded proof of stable startup. No production, W:, `sabalanerp-local`, or #436 checkpoint state belongs to this probe.

## Required new design before a no-data probe

The next review must provide a complete no-systemd **process owner** with commands and tests for the actual Debian distro. It must pin the distro, binaries, package versions and hashes, native Engine ID, data root and socket. It must establish the QA daemon's exact PID, birth ticks, executable, arguments, namespace inode and socket ownership. The zero-state path refuses a pre-existing manual daemon even if it appears idle; stale PID/socket files or an uncertain owner also refuse. Neither broad process kills nor WSL shutdown are acceptable.

The launcher must keep the named `sabalanerp-qa` network namespace and user-space `slirp4netns` uplink alive without systemd, then start native `dockerd` **inside that namespace** with the protected selector's exact `--host=unix:///run/docker.sock`, `--data-root=/var/lib/docker`, `--bridge=none` and `--iptables=true` arguments. It must verify the daemon PID/birth/FD9/pidfd and socket owner, and refuse if the named namespace, controller, daemon and plan-pinned inode differ or if any daemon manages iptables in the WSL initial namespace. A new namespace inode requires a newly reviewed private plan. The process owner must specify exact bounded teardown on success, timeout, signal, shell exit and partial start; it must not remove unknown pre-existing resources or enable an automatic restart into the initial namespace.

The separately reviewed no-data probe must then demonstrate all of the following before any image import, service creation or restore:

1. Initial WSL/Desktop namespace rules, routes, links, Docker Engine ID and six local service identities are byte-identical before and after; both #436 checkpoints remain unchanged.
2. The named QA namespace and native daemon have the same `net:[inode]`, distinct from the WSL/Desktop initial inode. The slirp TAP, private resolver and DNS forwarder work without exposing host loopback; the initial resolver must not point to loopback because slirp's DNS forwarder can otherwise leak that path ([slirp4netns manual](https://github.com/rootless-containers/slirp4netns/blob/master/slirp4netns.1.md)).
3. A temporary Docker private bridge, tested without importing a container image, carries direct publisher TXT DNS and certificate-verified ClamAV HTTPS. No proxy, TLS bypass, host-side port forward, or initial-namespace bridge/rule/route change is allowed. Any temporary probe namespace name must be created from a persistent mount namespace; `ip netns exec` uses a temporary mount namespace.
4. A known-live initial-namespace loopback listener cannot be reached through the slirp gateway, while a QA-only loopback listener cannot be reached from initial WSL, Desktop, the probe peer, or the host. Positive controls must still respond, so a closed-port failure cannot masquerade as isolation.
5. The independent off-computer QA backup endpoint resolves to its reviewed address and accepts only a read-only, strict-host-key SFTP `pwd` using the QA-only key. No production backup endpoint or key, upload, checkpoint transfer or data mutation is part of this probe.

The executable launcher and bounded probe are **not yet implemented**. Their current blockers are the absent slirp package and measured installed binary hash, the missing reviewed off-computer QA SFTP endpoint/key/known-host proof, and the missing complete owner/probe code that demonstrates the private bridge, positive and negative loopback controls, cleanup, and unchanged Desktop/initial namespace evidence. The preflight passing in a future state would close none of those gaps. Each failure leaves #439 and #432 NO-GO. A later no-systemd launcher and probe require independent review **before execution**; the existing protected controller selector and production deployment defaults remain unchanged.
