# #439 private network namespace: NO-GO on the current Debian host

The actual D:-backed WSL distro is **`sabalanerp-qa-debian`**, with PID 1 `init` and `/etc/wsl.conf` containing `[boot] systemd=false`. The earlier version of this runbook used `systemctl` to stop, mask and start Docker and slirp units. Those commands cannot operate on this host. **Do not run the old procedure, create `sabalanerp-qa`, install slirp, stop or restart dockerd, create a bridge, import an image, or run a restore or rehearsal under that procedure.** The current result is #439 NO-GO and #432 NO-GO. The host evidence is in [the #439 WSL report](../../reports/qa/protected-rehearsal-439-wsl-host-20261112.md).

This correction does not authorize changing `systemd=false`, terminating or shutting down WSL, or changing Docker Desktop. The owner chose the no-systemd Debian image to avoid the observed Ubuntu startup instability. A switch to systemd would require a separately reviewed host decision and bounded proof of stable startup. No production, W:, `sabalanerp-local`, or #436 checkpoint state belongs to this probe.

## Read-only evidence that remains valid

An operator may record, without starting or stopping services, the distro name, `cat /etc/wsl.conf`, `/proc/1/comm`, initial namespace inode (`readlink /proc/self/ns/net`), Docker Desktop namespace/Engine ID and the six `sabalanerp-local` container IDs, image IDs, start times and health. Use the Desktop context for Desktop captures and the explicit native QA Unix socket for any QA Engine query. The same Desktop service identities must be observed before and after any later reviewed probe. Check `docker compose -f docker-compose.local.yml ps` before any Docker action, as AGENTS.md requires. Do not use the QA socket for the Desktop census. Record command exit statuses and output provenance; a missing or timed-out read is a failed observation, not a pass.

The read-only [evidence verifier](../../deploy/scripts/verify-qa-netns-evidence.mjs) now requires `host-pid1.before`/`.after` and `host-wsl-config.before`/`.after` in addition to the existing network and Docker snapshots. The PID 1 files are the exact output of `cat /proc/1/comm`; the configuration files are the full bytes of `cat /etc/wsl.conf`. It refuses the present WSL-init, `systemd=false` host even if all other snapshots match. Passing synthetic verifier tests does not qualify the host or authorize mutations.

## Required new design before a no-data probe

The next review must provide a complete no-systemd **process owner** with commands and tests for the actual Debian distro. It must pin the distro, binaries, package versions and hashes, native Engine ID, data root and socket. It must establish the QA daemon's exact PID, birth ticks, executable, arguments, namespace inode and socket ownership. Before stopping a pre-existing manual daemon, it must prove that daemon owns the native QA socket, is distinct from Docker Desktop, has zero QA containers and no active operation, and can be stopped by a bounded TERM to that one verified PID. Stale PID/socket files or an uncertain owner must stop the procedure; neither broad process kills nor WSL shutdown are acceptable.

The launcher must keep the named `sabalanerp-qa` network namespace and user-space `slirp4netns` uplink alive without systemd, then start native `dockerd` **inside that namespace** with the protected selector's exact `--host=unix:///run/docker.sock`, `--data-root=/var/lib/docker`, `--bridge=none` and `--iptables=true` arguments. It must verify the daemon PID/birth/FD9/pidfd and socket owner, and refuse if the named namespace, controller, daemon and plan-pinned inode differ or if any daemon manages iptables in the WSL initial namespace. A new namespace inode requires a newly reviewed private plan. The process owner must specify exact bounded teardown on success, timeout, signal, shell exit and partial start; it must not remove unknown pre-existing resources or enable an automatic restart into the initial namespace.

The separately reviewed no-data probe must then demonstrate all of the following before any image import, service creation or restore:

1. Initial WSL/Desktop namespace rules, routes, links, Docker Engine ID and six local service identities are byte-identical before and after; both #436 checkpoints remain unchanged.
2. The named QA namespace and native daemon have the same `net:[inode]`, distinct from the WSL/Desktop initial inode. The slirp TAP, private resolver and DNS forwarder work without exposing host loopback; the initial resolver must not point to loopback because slirp's DNS forwarder can otherwise leak that path ([slirp4netns manual](https://github.com/rootless-containers/slirp4netns/blob/master/slirp4netns.1.md)).
3. A temporary Docker private bridge, tested without importing a container image, carries direct publisher TXT DNS and certificate-verified ClamAV HTTPS. No proxy, TLS bypass, host-side port forward, or initial-namespace bridge/rule/route change is allowed. Any temporary probe namespace name must be created from a persistent mount namespace; `ip netns exec` uses a temporary mount namespace.
4. A known-live initial-namespace loopback listener cannot be reached through the slirp gateway, while a QA-only loopback listener cannot be reached from initial WSL, Desktop, the probe peer, or the host. Positive controls must still respond, so a closed-port failure cannot masquerade as isolation.
5. The independent off-computer QA backup endpoint resolves to its reviewed address and accepts only a read-only, strict-host-key SFTP `pwd` using the QA-only key. No production backup endpoint or key, upload, checkpoint transfer or data mutation is part of this probe.

Each failure leaves #439 and #432 NO-GO. A later no-systemd launcher and probe require independent review **before execution**; the existing protected controller selector and production deployment defaults remain unchanged.
