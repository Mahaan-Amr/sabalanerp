# مبنای قابلیت‌های سپیدار برای ارزیابی جایگزینی حسابداری

تاریخ بررسی: ۲۰۲۶-۰۹-۲۷. منبع این یادداشت فقط صفحات رسمی شرکت سپیدار سیستم است. این فهرست **قابلیت‌های قابل عرضهٔ سپیدار** را نشان می‌دهد؛ به‌تنهایی ثابت نمی‌کند هر ماژول در نصب مورد استفادهٔ سبلان خریداری، فعال یا عملاً استفاده شده است. برای تعیین دامنهٔ جایگزینی، باید آن را با قرارداد/قفل نرم‌افزار، داده‌های پشتیبان، مدارک عملیاتی و تصمیم‌های ثبت‌شدهٔ پروژه تطبیق داد. وجود جدول در پشتیبان نیز به‌تنهایی شاهد استفادهٔ عملیاتی از گردش آن نیست.

## مرز شواهد برای قضاوت «یکسان بودن»

1. این صفحات کاتالوگ محصول و آموزش سازنده‌اند؛ نسخه، لایسنس و تنظیمات سپیدار سبلان را اثبات نمی‌کنند. بخشی از قابلیت‌ها صراحتاً زیرسیستم جداگانه‌اند. معیار مناسب، **برابری گردش کار مورد نیاز سبلان** است، نه کپی کردن تمام محصولات فروشنده.
2. پشتیبان پایگاه داده می‌تواند حضور داده، ساختار کدینگ، اسناد، طرف‌حساب‌ها، مانده‌ها و الگوهای واقعی استفاده را نشان دهد؛ اما به‌تنهایی عملکرد رابط، مجوزهای خریداری‌شده، صحت مانده‌ها یا امکان چاپ/ارسال خروجی قانونی را اثبات نمی‌کند. این‌ها به آزمون گردش کار و تطبیق گزارش نیاز دارند.
3. برای هر قابلیت باید زنجیرهٔ «مدرک مبدأ → فرم/تصویب/اصلاح و ردپا → ثبت حسابداری یا استثنای صریح → گزارش رسمی و قابل تطبیق» با دادهٔ واقعی و کاربر مجاز بررسی شود. صرف وجود API، جدول یا صفحه شاهد برابری نیست.
4. صفحات رسمی گاه از واژه‌های تبلیغاتی مانند «کامل» استفاده می‌کنند؛ در این یادداشت فقط عملیات و خروجی‌های مشخص فهرست شده‌اند. ویژگی‌های قانونی وابسته به تاریخ‌اند و باید در زمان آزمون عملی با مرجع قانونی و نسخهٔ مورد استفاده دوباره تأیید شوند.
