# چک‌لیست QA فاز ۱ منابع انسانی

این فهرست برای بازبینی شاخه `ferpheri` قبل از ادغام است. موارد «بحرانی» باید پیش از merge موفق باشند.

## ۱. دسترسی و مسیرها — بحرانی

- [ ] کاربر بدون دسترسی HR پاسخ 403 از `/api/hr/*` می‌گیرد و صفحات HR برای او قابل استفاده نیستند.
- [ ] دسترسی `view` داشبورد، ساختار و پرسنل را می‌خواند ولی عملیات ثبت/ویرایش را انجام نمی‌دهد.
- [ ] دسترسی `edit` تعاریف و پرسنل را تغییر می‌دهد ولی مهاجرت را اجرا نمی‌کند.
- [ ] فقط `admin` صفحه و API اجرای مهاجرت را در اختیار دارد.
- [ ] لینک‌های HR فقط به چهار مسیر موجود اشاره می‌کنند و لینک مرده Payroll/Attendance/Reports دیده نمی‌شود.

## ۲. طراحی و تجربه کاربری

- [ ] هر چهار صفحه در حالت روشن و تاریک، RTL و فونت فعلی پروژه درست نمایش داده می‌شوند.
- [ ] عرض‌های ۳۶۰، ۷۶۸، ۱۲۸۰ و ۱۹۲۰ پیکسل بدون بریدگی افقی ناخواسته قابل استفاده‌اند.
- [ ] تقویم‌های تاریخ شروع/پایان شمسی‌اند و تاریخ ذخیره‌شده پس از بارگذاری مجدد همان روز را نشان می‌دهد.
- [ ] حالت بارگذاری، خطای API، صفحه خالی، عملیات موفق و دکمه غیرفعال واضح‌اند.
- [ ] منو و Back navigation کاربر را به مسیر درست برمی‌گردانند.

## ۳. ساختار سازمانی — بحرانی

- [ ] واحدهای COMPANY، DIVISION، DEPARTMENT، SECTION و TEAM قابل ثبت‌اند.
- [ ] کد واحد تکراری رد می‌شود.
- [ ] واحد نمی‌تواند والد خودش یا یکی از فرزندانش شود.
- [ ] غیرفعال‌سازی واحد، تاریخچه را حذف نمی‌کند و آن را از انتخاب‌های جدید خارج می‌کند.
- [ ] محل کار و مرکز هزینه مستقل از درخت سازمانی ثبت و غیرفعال می‌شوند.
- [ ] شغل بدون ساختن جایگاه قابل ثبت است و در چند جایگاه قابل استفاده است.

## ۴. جایگاه، ظرفیت و گزارش‌دهی — بحرانی

- [ ] ساخت جایگاه بدون Job یا Organizational Unit رد می‌شود.
- [ ] ظرفیت صفر، منفی یا اعشاری رد می‌شود.
- [ ] خط گزارش‌دهی چرخه‌ای رد می‌شود.
- [ ] کاهش ظرفیت به کمتر از تخصیص‌های متعهد رد می‌شود.
- [ ] داشبورد Active، Committed و Vacancy را جدا نشان می‌دهد.
- [ ] تخصیص Acting ظرفیت را مصرف نمی‌کند و Vacancy دائمی را نمی‌بندد.
- [ ] تخصیص Primary و Secondary ظرفیت را مصرف می‌کنند.
- [ ] استخدام Planned همان جای خالی را برای استخدام دوم قابل استفاده باقی نمی‌گذارد.

## ۵. پرسنل و User — بحرانی

- [ ] پرسنل بدون حساب ERP قابل ثبت است.
- [ ] یک User آزاد را می‌توان به یک Personnel متصل کرد.
- [ ] User متصل‌شده برای اتصال دوباره نمایش داده نمی‌شود و API اتصال دوم را رد می‌کند.
- [ ] ایجاد Personnel، رابطه استخدامی و تخصیص اصلی یا کاملاً موفق می‌شود یا هیچ رکورد ناقصی باقی نمی‌گذارد.
- [ ] کد ملی خالی برای رکورد موقت مجاز است.
- [ ] کد ملی نامعتبر رد و کد ملی معتبر تکراری رد می‌شود.
- [ ] نام مشابه بدون تأیید صریح رد می‌شود؛ پس از بررسی و تأیید قابل ثبت است.
- [ ] شماره پرسنلی تکراری رد می‌شود.

## ۶. رابطه استخدامی و تخصیص‌ها — بحرانی

- [ ] رابطه Planned ظرفیت را متعهد می‌کند ولی در Active Headcount شمرده نمی‌شود.
- [ ] رابطه با تاریخ شروع آینده پیش از موعد Active نمی‌شود.
- [ ] Suspension ظرفیت جایگاه را آزاد نمی‌کند.
- [ ] دو رابطه استخدامی هم‌پوشان برای یک Personnel رد می‌شود.
- [ ] دو Primary هم‌زمان برای یک رابطه رد می‌شود.
- [ ] Secondary بیش از ظرفیت جایگاه رد می‌شود.
- [ ] تخصیص باید کاملاً داخل بازه رابطه استخدامی باشد.
- [ ] انتقال/ارتقا Primary قبلی را بدون حذف تاریخ می‌بندد و Primary جدید می‌سازد.
- [ ] Primary به‌تنهایی با «پایان تخصیص» بسته نمی‌شود.
- [ ] پایان Employment از endpoint عمومی وضعیت رد می‌شود و منتظر فاز Offboarding می‌ماند.

## ۷. سرپرست مسئول — بحرانی

- [ ] اگر جایگاه سرپرست یک متصدی معتبر دارد، همان Assignment خودکار انتخاب می‌شود.
- [ ] اگر چند متصدی دارد، ثبت زیردست بدون انتخاب مسئول رد می‌شود.
- [ ] مسئول انتخابی باید در Position سرپرست باشد.
- [ ] بازه Assignment مسئول باید کل بازه مسئولیت را پوشش دهد.
- [ ] جایگاه سرپرستی خالی در صف کنترل کیفیت داشبورد دیده می‌شود.

## ۸. مهاجرت — بحرانی

- [ ] Preview هیچ تغییری در پایگاه داده ایجاد نمی‌کند.
- [ ] تعداد Personnel فعال/غیرفعال، User متصل/آزاد، Department، Schedule و Exception با منبع تطبیق دارد.
- [ ] نام‌های تکراری و پرسنل غیرفعال در Conflict report ظاهر می‌شوند.
- [ ] فقط Departmentهای تأییدشده به Organizational Unit تبدیل می‌شوند.
- [ ] `createdAt` قدیمی به‌عنوان hire date استفاده نمی‌شود.
- [ ] Personnel فعال یک رابطه ACTIVE با migration baseline و `startDateVerified=false` می‌گیرد.
- [ ] اجرای دوباره همان مهاجرت رکورد تکراری نمی‌سازد.
- [ ] source ID، source system و migratedAt حفظ می‌شوند.
- [ ] Exceptionهای قدیمی در این فاز به‌زور Leave تبدیل یا حذف نمی‌شوند.
- [ ] پس از مهاجرت، رابطه‌های فاقد Primary در صف کنترل کیفیت دیده می‌شوند.
