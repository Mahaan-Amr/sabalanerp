# فضای کاری منابع انسانی

## وضعیت

فاز ۱ پیاده‌سازی شده و برای بازبینی مدیر روی شاخه `ferpheri` آماده است. این فاز پایه مشترک ساختار سازمانی و استخدام را فراهم می‌کند و عمداً شامل جذب، مرخصی، حقوق، اسناد و Offboarding نیست.

## صفحات فاز ۱

- `/dashboard/hr` — داشبورد سرانه فعال، ظرفیت متعهد، جای خالی و صف کنترل کیفیت
- `/dashboard/hr/structure` — واحدهای سازمانی، محل‌های کار، مراکز هزینه، شغل‌ها و جایگاه‌ها
- `/dashboard/hr/personnel` — هویت پرسنلی، رابطه استخدامی و تخصیص‌های تاریخ‌دار
- `/dashboard/hr/migration` — پیش‌نمایش و اجرای کنترل‌شده مهاجرت داده‌های موجود

## مرزهای مالکیت

- `Personnel` هویت فرد شاغل است؛ `User` فقط دسترسی سامانه را نشان می‌دهد.
- `Job` ماهیت کار است؛ `Position` جای آن کار در ساختار و دارای ظرفیت است.
- واحد سازمانی سلسله‌مراتب سازمان را نشان می‌دهد؛ محل کار و مرکز هزینه مستقل هستند.
- رابطه استخدامی دوره اشتغال را نگه می‌دارد؛ تخصیص جایگاه تاریخچه محل خدمت و مسئولیت را نگه می‌دارد.
- تخصیص اصلی و ثانویه ظرفیت مصرف می‌کنند؛ Acting جای خالی دائمی را پر نمی‌کند.
- پایان استخدام در آینده فقط از جریان مستقل Offboarding انجام می‌شود.

## قواعد اعمال‌شده در API

- سطح `view` برای خواندن، `edit` برای تغییر پایه و `admin` برای مهاجرت لازم است.
- چرخه در سلسله‌مراتب واحدها و خط گزارش‌دهی جایگاه‌ها رد می‌شود.
- ظرفیت جایگاه برای تخصیص اصلی و ثانویه کنترل می‌شود.
- هر رابطه استخدامی در هر لحظه فقط یک تخصیص اصلی دارد.
- انتقال یا ارتقا، تخصیص اصلی قبلی را تاریخ‌دار می‌بندد و رکورد جدید می‌سازد.
- جایگاه دارای چند متصدی سرپرست، انتخاب صریح یک سرپرست مسئول را الزامی می‌کند.
- محدوده مسئولیت سرپرست باید کل بازه تخصیص زیردست را پوشش دهد.
- کد ملی در صورت ثبت اعتبارسنجی و یکتا می‌شود؛ رکورد موقت می‌تواند بدون کد ملی ایجاد شود.
- نام مشابه اخطار می‌دهد و برای ادامه تأیید صریح می‌خواهد.
- مهاجرت تکرارپذیر، دارای provenance و بدون حذف داده قدیمی است.

## ترتیب پیشنهادی مراحل بعد

1. جذب و Onboarding بر پایه Job، Position، ظرفیت و Responsible Supervisor
2. برنامه کاری و مرخصی با یک منبع حقیقت HR و مصرف نتیجه توسط حراست
3. قراردادها، اسناد طبقه‌بندی‌شده و Offboarding
4. حقوق، عملکرد، آموزش و گزارش‌های تکمیلی

جزئیات تصمیم‌های دامنه در `CONTEXT.md` و ADRهای `docs/adr/0012` تا `0018` ثبت شده‌اند.
