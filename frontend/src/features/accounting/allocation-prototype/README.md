# نمونه موقت تخصیص مشتری

پرسش: برای تخصیص گروهی، ورود مبلغ در جدول (A)، پنل منابع کنار جدول (B)، یا انتخاب و پنجره متمرکز (C) مناسب‌تر است؟

تصمیم‌های تأییدشده در ۲۰۲۶/۱۰/۲۸: ردیف بدهی قطعی زیر قرارداد؛ تکمیل مانده فقط به‌صورت پیشنهاد با تأیید حسابدار؛ واحد تومان با حفظ دقت یک ریال (یک رقم اعشار تومان).

اجرا: `npm run prototype:customer-allocation`. این فرمان فقط فایل‌های نمونه را به frontend توسعه موجود در `sabalanerp-local` منتقل می‌کند؛ سرویس و پایگاه تازه نمی‌سازد. حساب مشتری را باز کنید و `?variant=A`، `?variant=B` یا `?variant=C` را به مسیر اضافه کنید. افزودن `&sample=demo` ورود اولیه را با داده آموزشی انجام می‌دهد. نوار پایین و کلیدهای جهت، طرح را عوض می‌کنند. صفحه بدون این پارامتر رفتار عادی دارد؛ نمونه در production غیرفعال است.

داده واقعی فقط از واکشی عادی پرونده خوانده می‌شود. برای مقایسه چند بدهی و منبع، «داده آموزشی چندقراردادی» را انتخاب کنید. تمام انتخاب‌ها، سهم‌ها و ثبت‌های نمونه فقط در حافظه‌اند؛ هیچ API مالی فراخوانی نمی‌شود. تغییر طرح پیش‌نویس را حفظ می‌کند؛ تغییر داده یا بازخوانی صفحه آن را پاک می‌کند. داده آموزشی به‌صراحت از اطلاعات واقعی تفکیک شده است.

منابع انتخابی به ترتیب نمایش، سهم پیشنهادی می‌دهند. سقف هر منبع قابل ویرایش است. تکمیل مانده فقط بدهی‌های منتخب را به ترتیب جدول و در سقف منابع منتخب پوشش می‌دهد. مرور نهایی سهم هر منبع، مانده بدهی‌ها و تأیید حسابدار را نشان می‌دهد. بازکردن نمونه وصول چک، مجوز استرداد یا تسویه مجاز ارسال را اثبات نمی‌کند؛ اجرای نهایی باید کنترل‌های مالک موجود مالی را حفظ کند.

نتیجه: منتظر مقایسه کاربر. هیچ طرحی هنوز برای تولید انتخاب نشده است. پس از انتخاب، پیاده‌سازی نهایی باید با کنترل‌های واقعی مالی بازنویسی شود؛ این کد موقت منبع اولیه مقایسه است.
