# مقایسهٔ رابط و کنترل‌کنندهٔ ایجاد قرارداد فروش عادی و فروش همکار

تاریخ بررسی: ۲۰۲۶-۱۰-۰۷. بررسی مستقیم کد فعلی؛ این گزارش مدعی اجرای مرورگر زنده نیست. اجرای QA جاری و جمع‌بندی گزارش با عامل اصلی است. هیچ کد محصولی در این بررسی تغییر نکرده است.

## مرزبندی مسیرها

- ورودی اصلی هر دو `/dashboard/sales/contracts/create` است. فایل `frontend/src/app/dashboard/sales/contracts/create/page.tsx:24`، `PartnerCreationRuntime` را با ordinary component تزریق‌شده اجرا می‌کند. نوع context تعیین می‌کند کدام کنترل‌کننده مونت شود؛ `PartnerCreationRuntime.tsx:1683-1686` برای ORDINARY_SALES ویو عادی و برای شریک غیر writable وضعیت ممنوع نمایش می‌دهد.
- «قرارداد همکاری در فروش» با فروش همکار اشتباه گرفته نشود: `/dashboard/sales/contracts/collaboration/create` در `page.tsx:19` همان کنترل‌کننده عادی را با `contractKind="collaboration"` اجرا می‌کند. این نوع مرحله پروژه را حذف می‌کند (`CreateContractWizardClient.tsx:799-815`)؛ کانال شریک مجزا است.
- فروش عادی: `CreateContractWizardClient.tsx` کنترل‌کننده بزرگ میزبان state، محصول، تحویل، مالی، بازیابی و تأیید است. شریک: `PartnerCreationRuntime.tsx` کنترل‌کننده context/lease/technical draft/inquiry/wizard و `PartnerContractWizard.tsx` کنترل‌کننده مرحله/قیمت/Case است. اشتراک view به معنای اشتراک کنترل‌کننده، state یا همه قواعد نیست.

## رفتار ناوبری، ثبت و بازیابی

1. ساخت عادی progress قابل کلیک نیست؛ edit mode قابل کلیک است و Submit روی همه مراحل edit نمایش دارد. هر next validation همان مرحله؛ submit در edit همه مراحل visible تا پرداخت را کنترل می‌کند، اما create در useContractSubmission.ts:125-128 فقط validateCurrentStep را فراخوانی می‌کند و سپس guards هویت/graph/پرداخت را دارد. در مرحله ۷ local validateCurrentStep هیچ case برای validation ندارد؛ مسیر عادی به validation مراحل پیشین در next تکیه می‌کند. partner مرحله آغازین date/customer/project/products دارد ولی progress هشت مرحله نمایش می‌دهد؛ پس از save graph و شماره‌دارشدن Case، wizard بخش retail/pricing/delivery/payment/confirmation وارد می‌شود. progress در Case شماره‌دار قابل کلیک، حتی با قیمت در انتظار؛ قبل از Case مرحله pricing به بعد به products برگردانده می‌شود. شواهد: `CreateContractWizardClient.tsx:5900-5911,6438-6476`; `PartnerCreationRuntime.tsx:71,1815-1846`; `PartnerContractWizard.tsx:62-70,194-198,371-409`.
2. کنترل next اولیه شریک فقط date/customer/project غیرخالی و technicalActionReady در products است؛ خطای مرحله در notice کلی، نه error prop فیلد مشترک date/customer/project. عادی error prop همین viewها را پاس می‌دهد و قابل نسبت‌دادن به field/group است. `PartnerCreationRuntime.tsx:1739-1752,1816-1827` در مقابل `Step1ContractDate.tsx:39`, `Step2CustomerSelection.tsx:111`, `Step3ProjectManagement.tsx:63`.
3. عادی create از useContractSubmission و مسیر عادی API و editSession استفاده می‌کند؛ موفقیت creation completion به detail/list route با actual number می‌رود، clear بازیابی فقط پس از confirmed response. شریک commandهای schema/version/idempotency، snapshot pending و فاز uncertain دارد؛ retry همان command و integrity checks. technical save، wizard save و Case submit سه مرز مجزا هستند. شریک finalize ابتدا in-flight wizard save را تمام می‌کند، API finalize را اجرا و به قرارداد projection هدایت می‌کند. `useContractSubmission.ts:350-478`; `PartnerCreationRuntime.tsx:1772-1786`; `partnerCaseSubmission.ts`.
4. عادی بازیابی draft گسترده، شامل جستجوها، پیکربندی modal، draft سه part پله، payment form، stage و graph؛ local journal + server recovery با debounce ۲۵۰ms و heartbeat ۲۵s. انتخاب resume/new، takeover، readonly boundary و بسته‌شدن overlay در revoke. `CreateContractWizardClient.tsx:2530-2633,2677-3008,6380-6433`; `useContractEditRecovery.ts:23-24,350-396`.
5. شریک بازیابی چند لایه: runtime localStorage actor/inquiry؛ entry snapshot sessionStorage actor/recovery؛ technical checkpoint ۶۰۰ms؛ wizard local snapshot و server autosave ۷۰۰ms؛ browser session lease reacquire قبل mutation، token/revision بررسی؛ hydration saved view تطبیق graph و approval؛ حفظ مقدارهای تحویل هنگام product edit، error به‌جای تصحیح خاموش. `PartnerCreationRuntime.tsx:119-126,332-348,377-435,645-735,779-786,988-1024,1113-1144`.
6. فرق مهم recoverability: ویرایش محصول شریک در state `modal.draft` داخل editor نگه داشته می‌شود؛ onDraftChange تنها setModal است، host technicalDraft تا onSave تغییر نمی‌کند. onClose فقط setModal(null)؛ هیچ autosave این modal و هیچ تأیید discard در این اتصال نیست. crash/refresh/escape/close می‌تواند تغییرات ذخیره‌نشده محصول را از بین ببرد. عادی product modal و stair drafts جزو autosave گسترده‌اند و پله explicit discard confirmation دارد. `PartnerTechnicalDraftEditor.tsx:318-322,325-360`; `CreateContractWizardClient.tsx:2900-2930,6335-6364`. این تفاوت از خود کد معلوم است؛ reproduce زنده برای زمان‌بندی crash و modal Escape توصیه می‌شود.
7. شریک raw localStorage.setItem در اثر wizard autosave می‌تواند Storage quota exception بدهد (`PartnerCreationRuntime.tsx:377-382`)؛ ordinary از persistContractLocalValue با failure notification استفاده می‌کند. این ریسک runtime نیازمند reproduction storage failure است؛ با موفق‌بودن تست happy-path بسته نمی‌شود.

## یافته‌های قطعی که به تصمیم طراحی/دامنه نیاز دارند

- تاریخ گذشته در شریک و عادی یک policy نیست؛ انتخاب تقویمی شریک بدون disablePastDates و تاریخ عادی با آن. backend مجاز/غیرمجازبودن جدا بررسی شود.
- اطلاعات انتخاب پروژه شریک تنها عنوان است؛ آدرس و مشخصات مدیر در card وجود ندارد و defaults تحویل از خود پروژه گرفته نمی‌شود. هر تغییری باید context schema و boundary مالکیت داده را نیز ببیند.
- exact decimal equality در شریک و tolerance .01 در عادی برای توزیع/پرداخت متفاوت است. این تفاوت صرفاً layout نیست.
- فقط شریک ریسک زیان، wholesale approval expiry، per-row rejection/reinquiry و دو رابطه تجاری را دارد. حذف مرحله pricing برای ظاهراً یکسان‌شدن UX، حذف rule محسوب می‌شود.
- modal finalization در PartnerContractWizard قابل دسترسی نیست: commitOpen فقط false initialize شده (`:123`) و همه setterها false هستند (`:278,280,289,419`). پس sheet و `commit()/onFinalize` از همین wizard باز نمی‌شوند. اقدام انتهایی واقعاً saveCompletedPartnerDraft/openCase است. این الزاماً فقدان finalization کل سامانه نیست؛ Case detail مسیر دیگری دارد، اما modal/callback این component کد مرده‌اند.
- شریک تصاویر محصول ندارد، عادی uploader دارد. scope بازتولید تصویر در خروجی شریک باید تصمیم باشد.
- summary شریک تاریخ ISO را مستقیم به FieldView می‌دهد؛ ordinary summaries Jalali stored value استفاده می‌کنند؛ display calendar مشترک به‌تنهایی parity نمایش summary نمی‌سازد.
- data sourceهای permission/scoping متفاوت‌اند: ordinary user permissions + CRM capabilities و response failures؛ شریک authoritative creation context و writable check. admin mock در آزمون routing معادل اثبات permissionهای persona واقعی نیست.

## یافتهٔ تکمیلی: نگاشت تحویل خدمات و ورودی اعداد فارسی

- فروش عادی خدمات مستقل را در مرحله تحویل نشان می‌دهد و مقدار آن را وارد `delivery.products` با `rowType:service` می‌کند (`Step6DeliverySchedule.tsx:148-166,343-405`). بااین‌حال هنگام submit، `useContractSubmission.ts:326-340` صریحاً همه `rowType:service`ها را از contractDeliveries حذف می‌کند؛ اگر هیچ محصول deliverable نباشد تمام deliveries را به [] تبدیل می‌کند. همین contractDeliveries به HTML و contractData تزریق می‌شود (`:356,372`). شریک serviceItems را در intent.deliveries نگه می‌دارد و `partnerDeliveryPlanIssue` توزیع کامل خدمت را الزام می‌کند. بنابراین اینکه UI عادی برنامه اجرای خدمت را عرضه می‌کند به معنی حفظ آن در خروجی ارسال نیست. این یکی از مهم‌ترین تفاوت‌های معنایی برای بررسی backend/output است.
- validation مرحله تحویل کنترل‌کننده عادی (`CreateContractWizardClient.tsx:5721-5804`) توزیع کامل deliverableProductEntries را جمع می‌زند، ولی هیچ حلقه مشابه برای schedulableServiceEntries ندارد؛ شریک برای serviceRows توزیع دقیق را هم کنترل می‌کند. اثر عملی API نهایی باید جدا اعتبارسنجی شود.
- نبود normalizeNumericText در handler مقدار سنگ شریک (`PartnerCreationRuntime.tsx:1483`) به‌تنهایی باگ ورودی رقم فارسی نیست: `ErpInput` با inputMode=decimal در `components/erp/index.tsx:271-274` رقم‌های فارسی/عربی را قبل onChange عادی‌سازی می‌کند؛ ورودی UI `:1491` همین primitive است. handler سرویس `:1512` normalize اضافی دارد. helper `partnerRetail.ts:decimal` نتیجه parse preprocess را استفاده نمی‌کند؛ فراخوانی برنامه‌ای با raw Persian string ممکن است fail کند، ولی آن را شکست UI تایپ رقم فارسی اعلام نکنید.
