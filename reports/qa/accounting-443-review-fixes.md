# Accounting #443 review fixes — local evidence

Observed 2026-11-15 on `codex/accounting-443-review-fixes`, based on integration `be696471`.

The dashboard change check uses transactional, 32-bucket write versions for ordinary and authorized Partner data. It always resolves current per-Case authority, including committed Cases without an invoice. Older row edits that retain `updatedAt`, inserts, deletes, customer presentation edits, and an authorized invoice-free Case with a false client hint were covered by focused service tests. Repeated unchanged checks did not advance revisions. The Partner payment grouping and Accounting return-route predicate were deduplicated without changing their callers' behavior.

The seven additive migrations cover Sales Contracts and their list children, financial records, receivables, payment statuses, tax, correction requests, Accounting audit and flags, Partner Case/profile/revision/payment-plan sources, CRM customer presentation fields, user names, Accounting settings, and periods. The Partner revision trigger uses its composite `(caseId, revision)` identity. The final ownership resolver follows invoice, receivable, contract, source-record, and polymorphic audit links before assigning a private version. A marked private snapshot with no resolvable owner can still be written, but advances no ordinary token because the Accounting read scope hides it. Conflicting Partner owners likewise advance no token. The owner-scope migration initially failed locally because its PL/pgSQL variable was named `references`; Prisma marked that attempt rolled back, the variable was corrected to `owner_refs`, and the migration then applied normally. No trigger bypass or manual SQL repair was used.

The compact dashboard's deadline source selects omit creator IDs, so its attached actor names are currently null. It also exposes Sales Contract creator and seller IDs without resolving their names. The user-name token remains conservative for possible future presentation, and a name edit on an evidence author can cause a rare unnecessary refresh. Ordinary contract summary attachments now exclude Partner-source linked rows even when an imported row carries an ordinary `contractId`; an ordinary flag remains in the summary and the authorized Partner review retains its private flag. The audit read scope also hides rows whose sole `entityId` points to a Partner correction or flag. Focused tests cover both privacy changes. The user-name trigger uses source-scoped evidence; an unrelated user edit leaves the ordinary token unchanged.

The summary's private-marker SQL now includes `id IN (financialIds)` inside the database predicate and skips the lookup when the selected contracts have no financial IDs. Those IDs come only from selected contract rows and their referenced invoice/source records. This removes the former global marker result scan and JavaScript post-filter; the existing mixed-source summary regression remains green.
