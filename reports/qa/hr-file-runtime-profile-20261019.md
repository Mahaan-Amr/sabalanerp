# Private HR file runtime composition, 2026-10-19

This component connects the actual HR hiring/duties multipart middleware and
initial Job Application/Personnel erasure routes to the existing native-owned
versioned file commands. It is private composition, not ordinary production
startup or release admission. No environment or request flag enables it.

The one-shot startup binding requires the genuine RuntimeWorkBoundary sharing
the global HTTP completion owner, every actual Personnel-plan storage root,
and genuine publications belonging to that same work context. Partial roots,
duplicate binding and binding after observation are refused. Even a health
request closes HTTP startup binding. Each multipart request retains its original
uploader; retain/discard cannot substitute a pathname-based owner.

Existing administrator password, target-name, fingerprint, reason and permission
checks precede the versioned erasure branch. Successful logical deletion returns
202 and FILE_CLEANUP_PENDING: immutable copies and original receipts remain held.
An error never retries the operation through raw legacy mutation. The canonical
legacy retry service refuses all cleanup in the bound versioned runtime; its
legacy expiry worker returns without querying or claiming legacy work. With no
private binding, existing legacy behavior remains unchanged.

## Actual acceptance

The fixture runs the real hiring, Personnel and duties routers over loopback
HTTP with an authoritative administrator session, the platform Prisma singleton,
an isolated real-schema PostgreSQL database and genuine Linux file publications.
It uses the existing sabalanerp-local candidate, not a second Compose stack.
