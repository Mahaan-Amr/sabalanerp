# #438 isolated protected rehearsal feasibility — 2026-11-12

## Decision

**NO-GO for a full protected-controller rehearsal in the current local topology.** This is a read-only assessment. It did not change Docker, the production capture, PostgreSQL, volumes, keys, or the #436 C:/D: checkpoints. A fixture run or a component restore would not meet #432's full-seam acceptance.

Subsequent read-only host inspection found a second independent blocker: the original protected controller requires Linux root on the actual Docker daemon host. `legacy-backend-signal.py:264-335,503-525` verifies `/run/docker.pid`, `/var/lib/docker/containers/<id>/config.v2.json`, `/proc` FD9 FLOCK and pidfd ownership. The only WSL2 distribution is `docker-desktop`; its shell has neither daemon-host path nor Node/Python. A Docker-socket client or a new Compose overlay cannot supply the required host birth/lock proof. A reviewed native Linux control host is mandatory before claiming the exact #432 seam.

The latest operator-provided `AGENTS.md` instruction requires all local runtime work to use the existing `sabalanerp-local` project and preserve its six services and data. It permits the reviewed candidate/retained overlays **only for real two-version realtime qualification**. #438 separately forbids altering any of those six instances or their named volumes, a second project/database service, and an ad-hoc replacement service.

## Required explicit decision

To make #438 executable, the repository owner must first approve and document one of these architecture boundaries: (1) a narrowly reviewed **same-project QA cohort** with its own backend, frontend, Inquiry and private Nginx ingress, QA-only mounts and database in the existing PostgreSQL service, plus an opt-in protected-controller target binding; or (2) a separate isolated production-like environment, which would explicitly revise the current single-Compose-project rule. Either choice must keep the six existing local instances, named volumes and #436 checkpoints intact, use separately attested immutable previous/candidate images, and pass the real lease, checkpoint, remote readback, maintenance and rollback gates. The first option is the smallest match to the user's existing-local-project preference, but the present realtime-only overlay instruction does not authorize it.

The fresh production-state checkpoint now exists, but **neither** the current local Compose boundary nor the Docker Desktop host-owner boundary can execute the full seam. A complete alternative is a real Linux rehearsal host with native dockerd, six private services and restored checkpoint, after explicit owner approval of a separate isolated environment and reference-aware capacity expansion. It must pin the exact six previous images, build/pin the candidate, keep all ingress private, run the real protected lease/checkpoint/migration/gate/rollback path twice, and preserve both acknowledged-write sets. The backup host's existing keys may reduce custody work, but its capacity and unrelated workloads must be protected. #438 and #432 remain open. No adapter code or tests were added because there is no permitted executable seam to test under the current boundary.
