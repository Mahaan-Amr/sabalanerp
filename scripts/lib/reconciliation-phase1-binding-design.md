# Phase 1 canonical lease binding — source proof and minimal candidate change

Status: design for independent review; no live execution, no change to the execution worktree, no acquisition authority. Existing test-only share probe is evidence only for one leaf on this host, not for ancestor stability, link handling, remote filesystem or crash semantics.

`C:/Users/mahan/.codex/worktrees/native-c3-execution-419/sabalanerp/scripts/lib/serial-physical/host-lease.ps1` opens `$file` with `[IO.File]::Open(..., FileMode.OpenOrCreate, FileAccess.ReadWrite, FileShare.None)` before emitting `LEASE_READY`. `host-lease.mjs` obtains `lstatSync(file)` only **after** READY and associates a new WeakMap entry with that child, not the old operation. Thus a pre-open path lstat and the post-READY lstat do not make the open atomic with an earlier file-identity decision; the current canonical API cannot receive a verified already-open file object, return OS file identity of its opened stream, or reject creation. A prior nonexistent/moved leaf can be created and a changed path can be opened before mismatch is detected. This is an effect even when no bytes are written. Independently checking after the open is valuable detection but not prevention.

Candidate minimum interface change, subject to separate approval and review:

1. Add a separate **opt-in** versioned entrypoint for this audit; preserve the established canonical behavior for its other callers. The parent validates explicit audit authority and freshly identifies a trusted exact root; reject UNC, reparse points, hard-link count other than one and unknown filesystem semantics. This is not satisfied by a Boolean from an untrusted or self-attested file.
2. Parent opens each ancestor with a handle that prevents delete/rename, verifies directory, no-reparse and file identity from the handle, and keeps handles through lease acquisition and the audit; open target metadata with no data access, share read/write but no delete, and verify its handle identity. Locks themselves are not held by the metadata handle. Test-only observed leaf sharing compatibility is insufficient to establish the semantics of full ancestor guarding, junction replacement, or behavior on the actual filesystem. Concurrent legitimate path management may see sharing violations and this is an explicit effect requiring bounded operational admission.
3. Child adds a narrowly scoped existing-only mode using `FileMode.Open` (never OpenOrCreate), same RW and `FileShare.None`. Before READY, get `FileIdInfo` from its actual SafeFileHandle and send a bounded structured readiness message. Parent compares serial and full file ID with the pinned leaf and retains all path-guard handles. Mismatch => no audit action; do not pretend that a child opened a wrong file without effect. The no-delete leaf/ancestors must be established before opening, or mismatched wrong-file open remains possible. Define checked close/reap/EOF and any failure custody before implementing cleanup. FileIdInfo vs Node stat format must not be equated without platform evidence.
4. Keep the canonical lease object original to the new audit process; the audit adds no rollback obligation for the historical operation and never closes or transfers that original process's in-memory tokens. The retained old case is documented `RETAINED_UNRESOLVED`, old EOF and safeState UNKNOWN. New lease release must require all new tracked audit work/readers/children closed, no new obligations, successful record of the audit result, and original new lease release protocol. On incomplete closure, guard loss, report failure or ambiguous release, retain the new owner/handle while reporting UNKNOWN; do not silently exit with a claim of protection.
5. A real audit additionally needs a reviewed operation-specific actor and resource census implementation with identity-bound evidence, root process/native scope/SQL/readers requirements appropriate to each precise read, and an actual durable receipt implementation (private DACL, exclusive path, write/fsync, known directory durability). No selected definitive scope-to-path map or current actor authority is available in the retained evidence. No arbitrary advisory SQL lock is required merely because SQL exists.

Source/test-owned proof still needed before a guarded adapter can be reviewed as executable: Win32 ancestor handle semantics and reparse/link resistance with same-file identity and actual PowerShell FileMode.Open/FileShare.None; swap/rename attempts while guard is held and after closure; correct custody/timeout/output and exclusive original child wait/EOF; tampered identity and census fail closed; private DACL and crash/receipt semantics. Tests must use new test-owned roots and preserve evidence. Do not test against `D:/sabalanerp-online-qa/deployment.lock`, real scope/DB, a live owner, runner, or Docker until separately authorized.

Current `reconciliation-readonly-phase1.mjs` is an injected state-machine scaffold; its Boolean port values are NOT independent evidence or user authority. `reconciliation-readonly-phase1-cli.mjs` is a diagnostic-only NOT_QUALIFIED CLI; its default ACL and directory durability are explicitly unverified. Neither is a completed adapter, durable report or live reconciliation procedure.
